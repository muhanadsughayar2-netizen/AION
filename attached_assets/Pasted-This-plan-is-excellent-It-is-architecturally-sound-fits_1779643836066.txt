There is one small technical correction you need to make before you start: The Gemini REST API does not have a generic urlContext tool. If you add { urlContext: {} } to the tools array, the API will likely return an error.

The Fix:
You are already doing the right thing by injecting the URL into the contents array as a message. Simply keep that part, and only add the googleSearch tool to the tools array. The model is intelligent enough to know that when it sees [Page to analyze: URL] in the conversation history, it should read it.

Why this works
Safety: By only adding googleSearch to the tools array, you avoid passing invalid tool definitions to the API.

Intelligence: Because you are injecting the URL text directly into the contents array, the Gemini model will naturally treat it as a "document" to analyze, and if it needs more info, it will automatically trigger the googleSearch tool (if enabled) to supplement the URL content.
