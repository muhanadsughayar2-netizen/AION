Summary of the Final Solution
The core issue is that Google Docs uses a Canvas to render text, which does not behave like a standard HTML input. The agent was reporting "success" because the hardware-level events were sent, but the Canvas simply ignored them [1]. To fix this, the agent now detects if it is on a Google Doc and switches to a "Direct Injection" method using a hidden internal iframe that Google Docs uses specifically for text input [2].

Key Findings
Google Docs (Canvas): You cannot "type" onto the canvas directly. You must target the .docs-texteventtarget-iframe and use execCommand('insertText'). This is the only method that bypasses the canvas barrier reliably [1].
Google Sheets (Grid): A single click only selects the cell. To trigger the blinking cursor (Edit Mode), the agent must send a double-click event via the Chrome Debugger (CDP) [3].
Word/Excel Online: These sites often use nested iframes (e.g., WACFrame). The agent's locateForType function must use getBoundingClientRect() on the iframe itself to calculate the correct global coordinates for the debugger to click [2].
Debugger Conflict: If you have the Chrome DevTools (F12) window open, the extension's debugger will fail to attach. Always close DevTools before testing the agent's typing features [3].
