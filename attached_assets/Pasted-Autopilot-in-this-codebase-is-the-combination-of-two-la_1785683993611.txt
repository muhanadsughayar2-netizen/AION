Autopilot in this codebase is the combination of two layers:

Maneuver Gallery (high-level, user-facing “recipes”)
Agent / CDP automation engine (low-level browser control that the maneuvers call)

Below is a complete map of what exists, what is incomplete or fragile, and what is missing if the goal is to make Autopilot remarkable.

C. Low-level Agent / CDP Engine (the real power)
This is the most sophisticated part of the codebase.
Background (background (11).js):

CdpSessionPool — ref-counted, mutex-serialized, auto-detach after 45 s idle.
Human-mimetic jitter (±2 px) on every mouse event.
Target.setAutoAttach so child windows / OAuth popups / AI Studio build previews stay under control.
Sub-session tracker for spawned targets.
clearAndInject helper to force a clean content-script injection.

Content script (content (5).js):

Full handleAgentAction switch with:
click, type, scroll, checkElement, hideGhostCursor
Special-cased paste/type paths for Google Docs, Word Online, PowerPoint Online, Excel Online (clipboard + virtual-canvas handling).
Smart scroll-target detection (largest scrollable container under viewport center).
Ghost cursor + element highlighting for visual feedback.
Grok input-bar restoration (defensive).
Special-site full-render styles (Docs, YouTube, Gmail).


This engine is already production-grade for a first-generation browser agent.

3. Architecture That Would Make Autopilot Remarkable
Layer 1 — Maneuver Registry (single source of truth)
JavaScriptconst MANEUVERS = {
  'aistudio-build': {
    name: 'AI Studio Build',
    icon: '🏗️',
    description: '...',
    requires: ['gemini-key'],
    steps: [ /* declarative or function */ ],
    estimatedTime: '45–90 s'
  },
  'cross-ai-verify': { ... },
  // future: 'docs-to-slides', 'email-to-task', 'research-digest', etc.
};
Gallery becomes a pure renderer of this registry. Adding a new maneuver = one object.
Layer 2 — Orchestrator (state machine)
textIdle → Planning → Executing (step N) → Observing → Deciding → Done / Failed / NeedsHuman
Every step emits events that the popup / side-panel / chat window can subscribe to:

maneuver:started
maneuver:step (with human-readable description + optional screenshot)
maneuver:waiting-for-user (e.g. captcha, login)
maneuver:completed / maneuver:failed

Layer 3 — Observation + Vision Feedback
After every critical action:

Capture a small viewport or element screenshot.
Send to Gemini Flash (or the same model already in use) with a short question:
“Did the expected UI appear? Is the reply ready? Is there a captcha?”
Branch on the answer.

This single loop turns the agent from “fire-and-hope” into “see-and-correct”.
Layer 4 — Planner (optional but transformative)
User types a goal → Gemini produces a short JSON plan of agent actions → orchestrator executes it.
This is how you go from two hard-coded maneuvers to dozens of useful ones without writing new code for each.
Layer 5 — Safety & UX polish

Explicit “Run Autopilot” confirmation with estimated time and sites that will be opened.
One-click Abort that kills the CDP session and cleans up.
Live progress card (even in the popup or a floating toast).
Automatic tab grouping or a dedicated “Autopilot workspace” window.
Record the successful run so the user can re-play or share the exact sequence.

You are not starting from zero. The low-level agent is already better than most open-source browser agents. The missing piece is the orchestration + observation + UX layer that turns those primitives into reliable, user-visible “maneuvers”.
Once the gallery is live, Cross-AI Verify is fully automated, and a progress + abort surface exists, Autopilot stops being a hidden experiment and becomes the product’s most remarkable differentiator.
