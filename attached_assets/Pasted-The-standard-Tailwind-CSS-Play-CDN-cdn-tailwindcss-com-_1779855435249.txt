The standard Tailwind CSS Play CDN (cdn.tailwindcss.com) and Lucide Script CDN (unpkg.com) fail to load under a Chrome Extension's strict Manifest V3 Content Security Policy. This causes the generated websites to load as plain, unstyled text.
Below is a complete, step-by-step guide with exact copy-pasteable files, templates, and system prompts to make your extension popup websites load.
Why Your Extension Builds are Breaking (The Root Cause)
In Chrome Extensions (Manifest V3), the default Content Security Policy (CSP) is:
code
Text
script-src 'self';
object-src 'none';
When you inject code into an inline <iframe> via srcdoc or a blob: URL inside your extension popup page:
The iframe inherits the host popup's CSP limits because it shares the chrome-extension:// origin.
Any attempt to execute a remote script (like <script src="https://cdn.tailwindcss.com"> or <script src="https://unpkg.com/..."></script>) is compiled as a major security violation and silently blocked by Chrome.
Therefore, Tailwind utility classes are never compiled, Lucide icons are never initialized, and the page renders unstyled.
To fix this, you must instruct Gemini to generate pure, self-contained HTML using custom vanilla CSS inside a <style> tag and pure inline SVGs for icons, completely bypassing CDN scripts.

Alternative Option: Running Full Tailwind inside Extension popup (A Secure Extension Hook)
If you absolute must let Gemini output Tailwind code using the original prompts, you can create a sandbox context inside the extension.
Create a file named sandbox.html inside your Chrome Extension directories:
code
Html
<!-- sandbox.html -->
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <script src="https://cdn.tailwindcss.com"></script>
  <script src="https://unpkg.com/lucide@latest"></script>
</head>
<body>
  <div id="app"></div>
  <script>
    // Listen to code message updates from parent popup chat windows
    window.addEventListener('message', (event) => {
      const { htmlCode } = event.data;
      if (htmlCode) {
        document.getElementById('app').innerHTML = htmlCode;
        try { lucide.createIcons(); } catch(e){}
      }
    });
  </script>
</body>
</html>
In your manifest.json:
code
JSON
"sandbox": {
  "pages": ["sandbox.html"]
}
Now, change your popup's main chat.html iframe:
code
Html
<iframe id="livePreview" src="sandbox.html" allow="fullscreen" style="width:100%; height:200px; border:none; display:none; background:#07070a;"></iframe>
And in chat.js:
code
JavaScript
function _showLivePreview(code) {
  const iframe = document.getElementById('livePreview');
  if (iframe && iframe.contentWindow) {
    // Securely post the message across the secure local sandbox boundary
    iframe.contentWindow.postMessage({ htmlCode: code }, '*');
    iframe.style.display = 'block';
  }
}
Now, because the frame runs inside a declared extension sandbox, Chrome relaxes the CSP constraints, enabling remote scripts to compile smoothly while keeping the host popup completely secure.
