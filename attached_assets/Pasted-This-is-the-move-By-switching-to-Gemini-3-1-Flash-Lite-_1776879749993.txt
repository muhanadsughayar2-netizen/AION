Part 1: The Code (Gemini 3.1 Flash-Lite)
Tell Replit to swap your current API call in snap-coach.js with this. It includes the correct 2026 endpoint and the lighter weight configuration.

JavaScript
// --- Updated for Gemini 3.1 Flash-Lite (April 2026) ---
const MODEL_ID = "gemini-3.1-flash-lite-preview";
const API_URL = `https://generativelanguage.googleapis.com/v1beta/models/${MODEL_ID}:generateContent?key=${USER_API_KEY}`;

async function getSnapResponse(userSpeech) {
  const payload = {
    contents: [{
      parts: [{ text: userSpeech }]
    }],
    generationConfig: {
      temperature: 0.7,
      topP: 0.8,
      topK: 40,
      maxOutputTokens: 250, // Keep it concise for voice
    }
  };

  const response = await fetch(API_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload)
  });

  const data = await response.json();
  return data.candidates[0].content.parts[0].text;
}
Part 2: The "Permission Link" Fix (Offscreen Document)
Since your app isn't a "browser" yet, you need to declare the Offscreen permission. This creates a hidden page that holds the microphone connection even if the user clicks away from the popup.

Copy-paste this directive to Replit:

"Crucial Update: We are not a website, we are a Chrome Extension. You must implement an Offscreen Document to handle microphone permissions and audio playback.

Manifest: Add "offscreen" to the permissions array in manifest.json.

Logic: When the user clicks the Mic, use chrome.offscreen.createDocument with the reason AUDIO_PLAYBACK and USER_MEDIA.

The Link: Create a small offscreen.html and offscreen.js. This is where the actual navigator.mediaDevices.getUserMedia call will live. This ensures the 'Connecting...' state resolves correctly and the browser treats us as a trusted app, not a random script."
