Unfortunately, this isn't something that can be done directly within a Chrome Extension. Here's why: **Technical Limitation:** - The "Mark-of-the-Web" (Zone.Identifier) is an NTFS alternate data stream that Windows/Chrome adds at the operating system level when files are downloaded - Chrome Extensions run in a sandboxed environment and don't have access to modify NTFS metadata - The Chrome Downloads API can trigger downloads, but can't control the Zone.Identifier that the OS adds **What users can do instead:** 1. **Right-click → Properties → Unblock** (single files) 2. **PowerShell command** (bulk removal): ```powershell Get-ChildItem -Path "C:\Users\YourName\Downloads" -Recurse | Unblock-File ``` 3. **Windows Group Policy** (prevent MOTW entirely): - `gpedit.msc` → User Configuration → Administrative Templates → Windows Components → Attachment Manager - Enable: "Do not preserve zone information in file attachments" **What I can add to your extension:** I could add a small note in the export/download dialog that tells Windows users how to unblock files, or include a `.bat` script alongside downloads that users can run. Neither a note nor a .bat file is worth it.
99 % of users will ignore them, and the 1 % who need them will still be annoyed.

I looked into that approach carefully, and unfortunately it won't work for several reasons: **Problems with that snippet:** 1. **Infinite loop** - The re-download triggers another `onCreated` event, which erases and re-downloads again, forever 2. **Blob URLs don't persist** - Your extension creates downloads from canvas data (blob URLs). After the first download completes, the blob URL is released and invalid - the re-download would fail or create empty files 3. **Erasing doesn't strip MotW** - The `chrome.downloads.erase()` API only removes the download from Chrome's history UI.
