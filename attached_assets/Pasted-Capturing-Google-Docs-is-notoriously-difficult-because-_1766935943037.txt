Capturing Google Docs is notoriously difficult because Google doesn't use standard HTML for the text; they use a complex Canvas/SVG rendering engine (the "Kix" engine) and Virtual Scrolling (they unload pages that are off-screen).

If your extension currently "takes just one image," it is likely because it cannot detect the true height of the document or the scroll container is wrong.

Here is the specific code fix to make Google Docs scrolling work.

Step 1: Update forceSpecialSiteFullRender in content.js
You need to aggressively hide the Google Docs UI (ruler, toolbar, menus) so the document takes up 100% of the screen. Replace your existing forceSpecialSiteFullRender block for Google Docs with this:

// In content.js inside forceSpecialSiteFullRender()

if (isGoogleDocs) {
    style.textContent = `
        /* 1. HIDE ALL GOOGLE DOCS UI CHROME */
        #docs-chrome, 
        #docs-header, 
        .docs-titlebar-buttons, 
        #docs-toolbar-wrapper, 
        .navigation-widget-view, 
        .docs-companion-app-switcher-container,
        #gb, 
        .docs-horizontal-scroll-bar, 
        .kix-paginated-view-header,
        .docs-titlebar, 
        .docs-menubar, 
        .docs-material-menu-button-bar,
        #docs-bars, 
        .docs-butterbar-container,
        #kix-vertical-ruler,
        .kix-vertical-ruler {
            display: none !important;
        }

        /* 2. MAXIMIZE THE EDITOR AREA */
        #docs-editor, 
        #kix-appview, 
        .kix-appview-editor {
            top: 0 !important;
            height: 100vh !important;
            width: 100vw !important;
            overflow-y: scroll !important; /* Force scrollability */
            background: #f8f9fa !important;
        }

        /* 3. HIDE SCROLLBARS FOR CLEAN CAPTURE */
        ::-webkit-scrollbar {
            display: none !important;
        }
    `;
    console.log('[SnapToAI] Google Docs: UI stripped and editor maximized for capture');
}
Step 2: Update findScrollableContainer
Google Docs does not scroll the window. It scrolls a specific div class called .kix-appview-editor. You must ensure your logic grabs this specific element.

Update your findScrollableContainerTier0 function:

// In content.js inside findScrollableContainerTier0()

'docs.google.com': [
    '.kix-appview-editor',  // <--- This is the key container for Docs
    '#docs-editor',
    '.kix-zoomdocumentplugin-outer'
],
And in findScrollableContainer, add this specific check before everything else:

// In content.js inside findScrollableContainer()

// GOOGLE DOCS SPECIFIC FIX
if (host.includes('docs.google.com')) {
    // We try to find the editor container
    const kixContainer = document.querySelector('.kix-appview-editor');
    if (kixContainer) {
        console.log('[SnapToAI] Google Docs container found!');
        return kixContainer;
    }
}
Step 3: Increase Scroll Delay for Google Docs (Crucial)
Google Docs uses a "Canvas" renderer. When you scroll via code, the text does not appear instantly. It takes about 800ms to 1500ms to "paint" the text onto the canvas. Your current delay might be too short, resulting in blank pages or a single page capture.

Modify the capture loop inside performFullPageCapture:

// In content.js inside performFullPageCapture() loop

    // ... existing scrolling logic ...

    // Scroll down by one viewport
