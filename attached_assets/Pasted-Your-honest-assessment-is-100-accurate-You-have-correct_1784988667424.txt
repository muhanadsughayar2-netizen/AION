Fix 1: Reading "Invisible" Content (Gap 1)
To read what is inside a Google Doc or Sheet, you must bypass the Canvas and look at the Accessibility Tree or the Internal Model.

The Technical Fix: Instead of snapshotPage, implement a readInternalContent tool that uses Runtime.evaluate to run a "Main World" script.
For Google Docs: There is a "secret" way to extract text by finding the internal closure_ variables on the docs-texteventtarget-iframe.
The Code Logic:
// Inject this via Runtime.evaluate
const getDocsText = () => {
  const iframe = document.querySelector('.docs-texteventtarget-iframe');
  const doc = iframe.contentDocument;
  // Find the internal Google property that holds the text model
  const key = Object.keys(doc).find(k => k.startsWith('closure_'));
  // This 'digs' into the obfuscated object to find the text stream
  return extractTextFromModel(doc[key]); 
};

Fix 2: Sheets Cell Targeting (Gap 2)
Your idea to borrow the "Excel Name Box" strategy is the most stable solution for Google Sheets. Trying to calculate X/Y coordinates for a canvas grid is a nightmare because of scrolling and frozen rows [1.3.2].

The Technical Fix: Implement a goToCell tool specifically for Sheets.
The Sequence:
Locate the Name Box: Target the input field with the ID #t-name-box (or use the AXTree to find the "Name Box" role) [1.4.8].
Type & Enter: Use Input.dispatchKeyEvent to type "B3" and press Enter.
The Result: Google Sheets will automatically scroll and focus the view on that cell.
Reading the Value: Once focused, the agent should read the Formula Bar (#formula-bar-text). This is standard HTML and is visible to your agent's current vision [1.3.9].
