 ensure your "Native Extension" build (v3.0.6) works correctly and remains cost-effective, here is the technical breakdown of the concept and the exact JSON structure required for the REST API.

Summary
The transition to "Native Extension" in Veo 3.1 Fast moves your app from simple frame-mimicry to temporal continuity. Instead of starting a new video from a static image, the model uses the latent state and motion data of the previous segment to "grow" the video by 7 seconds. This preserves the physics, lighting, and audio key, resulting in a single, seamless .mp4 file.

2. The Correct REST JSON Shape
You mentioned "gambling" on the JSON structure. In the Gemini API generateVideos method, the video parameter expects a reference to a previously generated video resource. Based on successful implementations and SDK behavior, the most reliable REST shape is:

{
  "model": "veo-3.1-fast-generate-preview",
  "prompt": "Your next narrative step here",
  "video": {
    "uri": "projects/YOUR_PROJECT/locations/YOUR_LOCATION/operations/YOUR_OPERATION_ID/generatedVideos/0"
  },
  "config": {
    "resolution": "720p"
  }
}
The "URI" is the key: It must be the full resource name or URI returned in the generated_videos[0].video field of the previous operation [3][4].
Fallback: If uri alone fails, the alternate shape used by Vertex-style endpoints is "video": { "resourceName": "..." }.
3. Core Concepts of Native Extension
Temporal Memory: Unlike your old "Frame Capture" method, Native Extension passes the motion vectors and audio frequency to the next generation. This is why the music doesn't cut—the model continues the existing waveform [1][4].
7-Second Increments: You cannot choose the extension length; the model always adds exactly 7 seconds per call [1].
The 141-Second Limit: You can only trigger an extension if the current video is 141 seconds or less. Once it hits 142s, the API will reject further extensions to prevent the file from exceeding the 148s hard cap [1][4].
48-Hour Persistence: Google stores the "extensable" version of the video for 2 days. Every successful extension resets this timer for the new, combined file [1].
