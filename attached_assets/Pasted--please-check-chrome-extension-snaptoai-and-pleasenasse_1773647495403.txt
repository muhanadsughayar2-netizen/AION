Deep-Dive: Technical Spec for "Developer Mode" (The 10x Debugger)
To move SnapToAI from a generic utility to a "must-have" developer tool, you need to solve the Context Gap. When a developer sees a bug, they look at the UI, but they think in logs and code. Your extension should bridge these two worlds.

Here is the technical blueprint for implementing Developer Mode.

### 1. The Architecture: Bypassing the Sandbox
Chrome extensions run in an "isolated world," meaning your content_script.js cannot directly read the console.error messages from the user's webpage. To capture logs, you must "inject" a script.

The Technical Workflow:

Injection: Use chrome.scripting.executeScript to inject a small snippet into the main page context (the "World").
Monkey-Patching: This snippet overrides console.error and console.warn to store the last 5-10 messages in a global array.
Communication: When the user triggers a "Snap," the injected script sends the log array back to your extension via window.postMessage.
Why this matters: Gemini can now see the Stack Trace alongside the Screenshot. This allows it to say, "The button is red because the API returned a 404 on line 42 of index.js," rather than just saying "The button looks broken."

### 2. The "Context Payload" (Structured JSON)
Instead of just sending an image, your API call to Gemini should be a "Multi-Part" prompt. You should construct a JSON object that looks like this:

{
  "screenshot": "base64_data",
  "metadata": {
    "url": "https://localhost:3000/dashboard",
    "page_title": "Admin Panel",
    "timestamp": "2023-10-27T10:00:00Z",
    "browser_info": "Chrome/118.0.0"
  },
  "debug_data": {
    "console_logs": [
      {"type": "error", "message": "Uncaught TypeError: Cannot read properties of undefined (reading 'map')", "source": "app.js:15"},
      {"type": "warn", "message": "Proptype mismatch in component <Chart />"}
    ],
    "html_snippet": "<div id='root'>...</div>" 
  }
}

Suggested Prompt:

"You are a Senior Full-Stack Engineer. I am providing a screenshot of a bug and the associated console logs. Your task is to: 1. Identify the visual error in the image. 2. Cross-reference it with the provided logs. 3. Provide a 'Root Cause' and a 'Fix Suggestion' in Markdown code blocks. Be concise."

Yes. Below is a practical JavaScript implementation for the Console Log Collector used in the proposed Developer Mode for SnapToAI - Screenshot to AI.
The goal is to capture recent console errors from the webpage and send them to the extension when a screenshot is taken.

1. Injected Script (Runs in Page Context)
This script overrides console.error and console.warn and stores logs in memory.

(function () {
  if (window.__snaptoai_logger_installed__) return;
  window.__snaptoai_logger_installed__ = true;

  const MAX_LOGS = 10;
  window.__snaptoai_logs__ = [];

  function storeLog(type, args) {
    try {
      const message = args.map(a =>
        typeof a === "object" ? JSON.stringify(a) : String(a)
      ).join(" ");

      const entry = {
        type,
        message,
        timestamp: new Date().toISOString(),
        stack: new Error().stack
      };

      window.__snaptoai_logs__.push(entry);

      if (window.__snaptoai_logs__.length > MAX_LOGS) {
        window.__snaptoai_logs__.shift();
      }

    } catch (err) {
      // fail silently
    }
  }

  const originalError = console.error;
  const originalWarn = console.warn;

  console.error = function (...args) {
    storeLog("error", args);
    originalError.apply(console, args);
  };

  console.warn = function (...args) {
    storeLog("warn", args);
    originalWarn.apply(console, args);
  };

})();
This script:

• keeps the last 10 logs
• captures message + stack trace
• avoids duplicate injection
